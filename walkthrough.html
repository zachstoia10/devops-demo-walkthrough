Devin DevOps Demo: Walkthrough

From no CI to a self-healing build, using a private copy of ZoomInfo's open-source gtm-ai-cli
Please note: The bug in Act 2 was planted by us on a private copy. It is not a real ZoomInfo incident. The code is a private copy of the public, MIT-licensed gtm-ai-cli repo. Nothing was deployed, and no ZoomInfo system or account was touched.

The situation

  • gtm-ai-cli is ZoomInfo's open-source command-line tool for searching and enriching company and contact data. It comes with 148 unit tests.
  • Nothing ran those tests automatically, so any change could be merged without a single test running.
  • Then a risky change arrived (planted for this demo): "retry when the server has an error". If the server had already done the work, such as creating a record or sending an export, a retry could do it twice.

What Devin did

Act 1: added a safety net
  • Given one sentence: check whether tests, type check and build run on pull requests, and if not, add that.
  • Confirmed nothing was running, then added a CI check that runs install, type check, tests and build on every pull request and every change to main.
  • Opened a pull request and reported back once it was green.
Act 2: fixed a broken build
  • A fresh session, given one sentence: read the failed log, explain the cause in plain English, fix it, and don't change any tests.
  • Traced the failing test back to the one line that changed in the retry logic.
  • Kept the safe retries (read-only lookups), blocked the risky ones (create, change, delete), and confirmed the build went green.

Outcome

  • Every change is now tested automatically. That's 148 tests, plus the type check and build, on every pull request.
  • The risky change was caught before it was merged. The new CI check turned the build red.
  • A tested fix is waiting for review. All 148 tests pass, and none of them were changed.
  • Nothing was merged or deployed without a person signing off.

Why it matters

  • Engineers stay on the roadmap. A red build usually means someone drops planned work to dig through logs. Here the cause was found and fixed in minutes.
  • One sentence in, finished work out. Each act started from a single plain-English request, the way a manager would ask a teammate.
  • It fixes the cause, not the symptom. The test was right, so Devin fixed the code and left the tests alone.
  • Anyone can follow it. The root cause was explained in plain English, not only in engineering terms.
  • People stay in control, and everything is on the record. Every change arrives as a pull request for an engineer to approve, and both sessions show every step.
